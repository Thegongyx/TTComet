# `pingpong_highlight.py` 多机位切视角自适应（第一阶段）改动说明（20261121）

- **日期**：`20261121`（2026-11-21）
- **涉及脚本**：`src/pingpong_highlight.py`（升级至 `v4.18`）、`webui/app/highlight_bridge.py`
- **影响范围**：命令行流水线（`src/pingpong_highlight.py`、`src/run_pipeline.py`）与桌面端 WebUI（`webui/app/highlight_bridge.py` 同步映射 `camera_mode` 参数）；固定单机位视频 100% 保持既有原生管线，零行为与视觉变化

## 一、背景与核心问题

在实际乒乓球赛事转播与多视角剪辑录像中，导播会在视频中途切换机位（例如：端线主全景机位 $\leftrightarrow$ 侧面平视机位 $\leftrightarrow$ 反向端线机位 $\leftrightarrow$ 球员面部特写 / 观众镜头）。旧版脚本假设全片机位固定，在全局范围仅提取**唯一一套**球台四角（`quad`）、球网线（`net_line`）、长边走廊（`corridor`）与透视单应性矩阵（`H`），在导播切视角视频中会引发五类连锁问题：

1. **球台 / 球网几何失配**：混合多个视角的球台框取中位数会产生错误的杂交几何，或直接将副机位正常打球区域当作离群值剔除；
2. **副机位真球被主走廊误杀**：切到侧面宽幅或近景机位后，球飞出主机位走廊边界被批量过滤；
3. **特写镜头伪球混入与跨切镜拉直线**：切到无球台的球员特写镜头时，球衣 Logo、手部/球拍反光易被连成假轨迹；切镜瞬间前后两个机位坐标突变，补帧或残影队列会拉出横跨全屏的折线；
4. **跨视角回合误判与无端腰斩**：球网方向由水平变为竖直（或正反机位 `NEAR/FAR` 互换）导致过网判定失效、误判出台或连续同侧落点中断正在进行的精彩回合；
5. **跨焦段球速失真**：近景机位像素位移显著大于远景全景机位，未做比例尺归一化会导致近景普通球虚高霸榜前置精彩集锦。

同时，考虑到现有固定单机位（含多球台俱乐部球馆）效果已经稳定，本次第一阶段改造确立硬性前提：**绝不影响任何单机位视频的既有效果**，且完全基于现有检测日志（`raw_detections.jsonl` / `.jsonl.gz`）完成，零额外推理与解码开销。

## 二、单机位视频“100% 零影响”安全架构设计

### 1. 主入口双分支严格隔离（`main`）
- 启动后先调用 `detect_camera_timeline` 对检测日志做轻量机位自检；
- 当判定 `is_multi == False` 时，**100% 原样执行既有单机位全部函数调用链**（`extract_table_geometry` $\rightarrow$ `filter_static_ball_candidates` $\rightarrow$ `filter_ball_by_corridor` $\rightarrow$ `build_main_ball_track` $\rightarrow$ `clean_ball_track_parabolic` $\rightarrow$ `interpolate_track` $\rightarrow$ `compute_ball_speed_table` $\rightarrow$ `detect_bounce_events` $\rightarrow$ `detect_rallies` $\rightarrow$ `render`），不引入任何额外切分或阈值变动。

### 2. 三重单机位防误判机制（`_same_camera_table_view` / `detect_camera_timeline`）
在默认 `--camera-mode auto` 下，必须检出 **$\ge 2$ 个不同帧互斥、各自连续稳定 $\ge 1.0\text{ s}$（累计 $\ge 1.2\text{ s}$）且成功拟合出几何** 的球台机位才会进入多机位模式，并专门针对单机位常见干扰设计三重保护：
1. **球员半遮挡子框保护**：当球员横跨台前遮挡半张球台（甚至遮挡达 `55%`）时，残余球台检测框高度包含于完整框内部（$\text{inter}/\min(\text{area}) \ge 0.85$）且至少有 **2 条未遮挡边钉死在原像素位置**（误差 $\le \max(14\text{ px},\, 0.015 \cdot \text{diag})$），自动识别为同一固定机位（导播变焦推拉或切机位时四条边会同时发生位移/缩放）；
2. **静止球网锚定保护**：若球网检测框中心位移 $\le 0.015 \cdot \text{diag}$ 且长度比在 $[0.80,\, 1.25]$ 内，即使球台框受遮挡局部收缩，仍归入同一机位；
3. **球馆同帧共存邻台剔除**：若某次级球台簇与高频主球台簇在任意 $\ge 2$ 帧中**同帧同时出现**（各自 `IoU >= 0.45`），证明它是球馆内的隔壁球台（仅在前景主台被完全遮挡的瞬间短暂成为离画面中心最近的检测框），直接从候选机位中剔除；`< 0.75s` 的短暂全遮挡缺口自动桥接回原机位。

## 三、第一阶段多机位切视角自适应核心实现

### 1. 机位时间轴识别、镜头切分与同机位几何聚合（`detect_camera_timeline`）
- **自动镜头切分（Shot Segmentation）**：基于球台/球网空间观测聚类、短暂漏检桥接与 `< 0.25s` 边缘毛刺吸收，将全视频划分为有序镜头序列 `shots`：
  - `cam_id = 0, 1, ...`：不同机位编号的稳定球台镜头（如端线主机位、侧面副机位等）；
  - `cam_id = None`（`NO_TABLE`）：持续 $\ge 0.85\text{ s}$ 的球员面部特写、观众席或慢放过场镜头；
  - 记录所有镜头切换帧集合 `cut_frames`，供后续追踪、回合判定与渲染阶段协同感知。
- **同机位跨镜头聚合几何**：将全片所有归属同一 `cam_id` 的帧汇总后独立调用 `extract_table_geometry`（副机位球台偏离中心时自动放宽 `center_dist_ratio` 重试），为每个机位独立生成高精度 `quad`、`net_line`、`corridor`、`homography`、邻台隔离区 `neighbor_zones` 及像素比例尺 `s_px_m`。

### 2. 按镜头隔离追踪、特写屏蔽与球速跨焦段归一化（`run_multi_camera_track_and_events`）
- **按机位分组去静止球**：同一机位名下的帧共享静止球频次统计，既避免机位 A 的背景静止白点漏网，又防止机位 A 的静止点坐标误杀机位 B 同一像素位置的正常运动球；
- **特写镜头自动静音**：`cam_id is None`（`NO_TABLE`）镜头直接跳过球候选提取，彻底阻断球员特写球衣白标、挥手反光混入残影；
- **镜头内严格隔离弹道管线**：在每个球台 `Shot` 内部使用当前镜头所属机位的 `table_geo` 独立执行长边走廊过滤、主球轨迹关联、像素重力标定、双侧抛物线离群净化、分段抛物线平滑补帧及落点/击球事件检测，**严禁跨切镜边界插值补帧或差分算速**；
- **跨焦段球速归一化**：以主机位比例尺 $s_{\text{ref}}$ 为基准，按 $\text{scale\_factor} = s_{\text{ref}} / s_{\text{cam}}$ 将各副机位像素球速折算为等效主机位像素速度，并结合各机位各自的单应性矩阵计算真实物理球速（$\text{km/h}$），使前置精彩集锦球速排序跨镜头公平可比。

### 3. 跨视角回合检测与特写收尾状态机（`detect_rallies`）
- **逐帧动态几何查询**：`_ball_side`（过网方位）与走廊出台判定不再写死单一全局几何，而是按当前帧所属 `cam_id` 动态读取对应机位的 `net_line` 与 `corridor`（自动适配端线机位水平球网与侧面机位竖直球网）；
- **回合中途切球台机位无缝续航**：当 `IN_PLAY` 进行中的回合跨越 `cut_frames` 切到另一球台机位时，**保持回合不断裂**，自动清空依赖旧机位坐标系的 `prev_side`、`out_of_table_run`、`same_half_count` 与速度差分滑窗 `traj_buffer`；若发球第一跳刚结束即遭遇导播切镜，将发球落点转为 `'PRE_CUT'` 跨镜通配标记，使切回新机位后的接发球落点仍能正常触发回合起点；
- **切入无球台特写干净收尾**：当回合结束后导播立即切入 `NO_TABLE` 球员庆祝特写时，等待短暂确认窗口后以 `ended_reason = "camera_cut_closeup"` 将回合终点精准回退至切镜前最后一帧真实球位置，避免拖入冗长空镜。

### 4. 小球台落点跨镜正反方位兼容（`filter_alternating_landings` / `build_landing_rally_index`）
- 正反端线机位或主副机位切换后，`NEAR / FAR` 半台定义可能发生翻转；
- 新增切镜分割点感知：若同一回合内相邻两次落点之间跨越了导播切镜点 `cut_frames`，自动重置半台交替状态 `last_half = None`，避免合法落点因跨镜方位翻转被交替过滤器误删。

### 5. 渲染端切镜点残影与特效瞬时清空（`render`）
- 当剪辑片段内部（例如跨机位长回合或前后缓冲 `pre/post-buffer`）经过导播切镜帧 `cut_frames` 时，渲染循环立即清空上一镜头残留的球彗尾 `trail`、`last_trail_f`、选手光环历史框 `prev_player_boxes`、粒子系统 `particles` 与浮动文字 `labels`，确保画面切换瞬间干净利落、无旧视角残影悬停。

## 四、兼容性与新增参数

- 原有全部 CLI 参数、默认行为、退出码语义及 `run_pipeline.py`、`webui/app/highlight_bridge.py` **100% 向后兼容**。
- 新增 CLI 与 WebUI 桥接参数：
  - `--camera-mode {auto,single,multi}`（默认 `auto`；WebUI 桥接键名 `camera_mode`）：
    - `auto`（默认推荐）：自动检测是否存在 $\ge 2$ 个稳定球台机位；单机位视频 100% 走原生单机位管线，多机位切镜视频自动启用分段几何与跨镜自适应；
    - `single`：强制使用传统全局单一球台/球网几何管线；
    - `multi`：显式启用镜头切分与无球台特写屏蔽（含单球台机位穿插长特写镜头的视频）。

   - 特写段伪球噪点 `0` 帧混入主轨迹，侧面机位超出主机位范围的宽幅回合点完整保留；
   - 第一回合在切入特写前以 `camera_cut_closeup` 精准收尾，第二回合跨越第 `270` 帧切镜点无缝衔接（`[195-335]` 不断裂），端到端渲染输出正常且切镜帧无跨屏残影。
